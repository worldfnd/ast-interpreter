# ast-interpreter

A small Rust interpreter for Noir's monomorphized AST (`noirc_frontend::monomorphization::ast`).

It can run the same AST over bn254 or Goldilocks and compare field-independent values such as integers,
booleans, arrays, tuples, and structs. `Field` values are deliberately never compared: a difference
there is expected rather than a divergence. The default build uses Noir only.

## Using it

```toml
[dependencies]
ast-interpreter = { git = "https://github.com/worldfnd/ast-interpreter.git", rev = "<rev>" }
```

Use `interpret` for self-checking programs with no inputs, or `interpret_with_inputs` when `main` takes
arguments. For `Prover.toml` inputs, use `inputs_from_prover_toml` and
`expected_return_from_prover_toml`.

Crates that pass Noir AST values into this interpreter must use the same pinned `noirc_frontend` and
`acvm` sources, spelled the same way. Cargo keys a git dependency on the URL *and* the reference, so
`branch = "x"` and `rev = "<head of x>"` are different sources: you get two `FieldElement` types and no
error until the two halves meet. `acvm::FieldElement` is selected at compile time.

The `mavros-oracle` feature is a placeholder. Its `mavros-compiler` dependency is commented out, so
enabling the feature fails the build with a `compile_error!` saying so.

Main exports: `interpret`, `interpret_with_inputs`, `inputs_from_prover_toml`,
`expected_return_from_prover_toml`, `Value`, `IntValue`, `DiffValue`, `DiffOutcome`, `FailureKind`,
`values_equivalent`, `outcomes_equivalent`, `outcome_is_tolerated`, and `InterpretError`.

`InterpretError` separates bad caller data (`InvalidInput`), runtime range errors
(`ValueOutOfRange`), invalid AST value shapes (`Type`), and interpreter invariant failures
(`Internal`). It and `FailureKind` are `#[non_exhaustive]`.

## Building and testing

Stable Rust. `.cargo/config.toml` raises `RUST_MIN_STACK` because Noir's frontend recurses past
libtest's default; it applies only when cargo runs from this directory.

```sh
cargo build
```

```sh
cargo test
cargo test --features goldilocks
```

Ignored tests drive the cross-field differential and corpus surveys. They require either Noir's
upstream corpus in a sibling `../noir` checkout or field dumps generated by the dump test. Corpus
smoke tests in the default suite self-skip when the sibling checkout is absent.

## Roadmap

Run the monomorphized Noir AST under Goldilocks through this interpreter, starting with the smallest
field-independent ProveKit circuits and expanding toward the full OPRF and passport stacks.

### Phase 1 — Noir compiler and core stdlib

- [ ] Preserve and apply `#[field(...)]` attributes on impl blocks, trait impls, associated methods,
  and module declarations, then gate bn254-only stdlib code and tests before elaboration.
- [ ] Rewrite comptime integer casts to operate directly on `Integer`/`BigInt`, converting to
  `FieldElement` only when the destination is actually `Field`.
- [ ] Add Goldilocks boundary tests for comptime `Field` arithmetic, casts, modulus builtins,
  associated numeric constants, and `Field`-kinded generics.
- [ ] Make the field module selectable: gate `field/bn254.nr`, make `is_bn254()` return false under
  Goldilocks, and size fallback comparison/decomposition from the active modulus.
- [ ] Add Goldilocks-safe `u64`/`u128` wrapping arithmetic, integer hashing, field comparison, and
  decomposition paths; retain the existing `u8`/`u16`/`u32` behavior.
- [ ] Scope the `noir-bignum` redesign before any limb width is fixed: its 120-bit limbs,
  `TWO_POW_240`/`TWO_POW_246` `Field` constants, and 31-byte packing all assume a modulus above 2^246, so Goldilocks needs a new limb size, quotient bound, and range-check scheme. Pick one non-native representation shared with the Phase 3 BN254 limbs rather than two.
- [ ] Add dual-field Noir tests for the compiler and reached stdlib modules. The phase is complete when
  a minimal package type-checks without tolerated dependency diagnostics.

### Phase 2 — First end-to-end circuits

- [ ] Start with ProveKit's `basic-2`, then `basic-3` and `basic-4`; cover successful assertions,
  deliberate failures, and the `basic-4` public return value.
- [ ] Add `rangechecks` as the first `Field::assert_max_bit_size` circuit.
- [ ] Use `noir-r1cs-test-programs/small-sha` as the first crypto smoke test, then add pure-Noir
  SHA-256 wrappers for message lengths 0, 1, 55, 56, 63, 64, and 65.
- [ ] Keep SHA lengths in `u64`, check them before narrowing, and derive length/state bytes with
  integer shifts and masks instead of passing them through `Field`.
- [ ] Route SHA compression to the Goldilocks-safe pure-`u32` Noir implementation, then run
  `noir_sha256` and `partial_sha256` start, continue, and finalize; defer Poseidon commitments.
- [ ] Add the field-independent passport utilities next: byte slicing and MRZ parsing, date
  conversion, age checks, expiry checks, and zero-padding checks.
- [ ] Require the expected SHA digest or utility result under both fields.

### Phase 3 — OPRF hash-only subcircuits

- [ ] Preserve the existing OPRF protocol by representing BN254 base and scalar field values as
  nine 30-bit `u32` limbs over Goldilocks; prototype multiplication and modular reduction first.
- [ ] Port BN254 Poseidon2 `t2`, `t3`, `t4`, `t8`, and `t16` over the non-native field while retaining
  the current constants, domain separators, and canonical known-answer outputs.
- [ ] Preserve 31-byte packing inside non-native BN254 values; use at most seven bytes only where
  data is intentionally packed into one native Goldilocks `Field`.
- [ ] Add focused circuit wrappers in this order: `generate_id_commitment`, `generate_query`,
  `merkle_leaf`, `compute_merkle_root_poseidon2`, then `generate_nullifier`. All of them wait on
  Phase 4's BabyJubJub constant port: `babyjubjub` is a package dependency of `oprf`, and its
  253-bit `Field` globals are elaborated even where unreachable. Wrap the public
  `generate_commitment`, which calls the two private commitment functions.
- [ ] Require the canonical BN254 hash outputs to remain unchanged across builds and across fields.

### Phase 4 — OPRF curve and signature subcircuits

- [ ] Port BabyJubJub coordinates, scalars, constants, and fixed-base tables to the non-native BN254
  representation.
- [ ] Implement non-native point validation, addition, doubling, inversion, scalar multiplication,
  and subgroup checks, including fixed-base and variable-base tests.
- [ ] Port EdDSA-Poseidon2 verification and the Chaum-Pedersen discrete-log equality proof.
- [ ] Replace BN254-valued `Field` parameters in the OPRF ABI with non-native structs, use integer
  types for Merkle depth/index, and return canonical limbs or bytes.
- [ ] Add `oprf_query_inner`, unblinding, credential-signature, and DLOG circuit fixtures before
  composing them.

### Phase 5 — Full OPRF and passport gates

- [ ] Run the complete ProveKit `oprf` entry point with non-native BN254 inputs and unchanged
  canonical known-answer outputs.
- [ ] Enable the Poseidon commitment half of `partial_sha256` through the same non-native path,
  followed by the modular passport circuits; keep RSA/bigint-dependent circuits as the final tranche.
- [ ] Expand the dual-field Noir corpus gate after the targeted circuits pass, with every remaining
  exclusion named and counted.

### Field-dependent by design (excluded from the gate, not a bug)

- [ ] `to_*_bytes`/`to_*_bits` with `N` over the field's modulus size: assert under Goldilocks; kept
  on the `KNOWN_FIELD_DEPENDENT` allowlist.
- [ ] `field_less_than` (unconstrained `Field` ordering) and `Field::sgn0` (parity of the canonical
  representative): both read the field's integer representative, which differs across moduli.

### Not planned

- [ ] `array_refcount`/`slice_refcount`: a faithful value needs copy-on-write refcount tracking the
  interpreter does not model, so left `Unsupported` rather than faked. Not used by any ProveKit
  circuit or its dependencies.
